# JTAG UVC scaffold review

Reviewed commit: `2b2d4e7`. Source files were not modified. This is a static review; no SystemVerilog/UVM simulator was available on PATH, and no compile or simulation result is claimed. A small JavaScript model of the checked-in TAP table and monitor branches reproduced the observation-length cases below; it is not a substitute for HDL simulation.

## Findings, in priority order

### 1. [P1] Function calls a task: compile blocker

Location: `src/jtag_monitor_bfm.sv:33-38`.

`handle_reset()` is a function but directly invokes the task `publish()`. A direct function-to-task call is illegal even though this particular task uses nonblocking mailbox `try_put`. Make `publish` a void function, or make reset handling a task with appropriate call sites. Acceptance: compile the actual file list on the target UVM simulator.

### 2. [P1] Virtual BFM handles target interfaces containing interface ports

Location: `src/classes/proxy/jtag_driver_proxy.svh:12-14`; same pattern in the monitor proxy. Both BFM interfaces contain a `jtag_if` modport port.

This combination is restricted by the virtual-interface language rules. Some tools accept it with a warning, so treat it as a portability blocker rather than claiming every simulator rejects it. Our original nested-concrete-proxy design avoids needing a virtual handle to the BFM itself. Move the concrete implementation into the static BFM scope with an abstract API package, or choose another legal binding arrangement. Do not simply suppress the warning and claim portability.

Reference: [DVCon, Working within the Parameters](https://dvcon-proceedings.org/wp-content/uploads/1087.pdf), discussion of interface ports and virtual-interface restrictions.

### 3. [P1] TMS reset never synchronizes the monitor

Location: `src/jtag_monitor_bfm.sv:47-59`.

`state_known` starts false and becomes true only on TRST assertion. The supplied smoke test uses TMS reset, while the driver initializes TRST high. Consequently every TCK edge is skipped and the monitor publishes no scans. Count consecutive known-high TMS samples even when unsynchronized, establish reset after five, and report TMS reset. Reset detection must also work after synchronization.

Acceptance: without ever asserting TRST, send five TMS-high clocks, then known IR and DR scans; require reset and scan observations within a timeout.

### 4. [P1] Capture is counted as a shifted bit

Location: `src/jtag_monitor_bfm.sv:61-67`.

The capture-state branch clears the buffers and then appends TDI/TDO on the same edge. That edge performs capture rather than a serial shift. Once reset synchronization is repaired, a four-bit scan produces a five-bit observation, with an extra leading sample. Clear at capture, append only when the pre-edge state is SHIFT_IR or SHIFT_DR, including the edge that exits Shift.

Static trace reproduction: TMS `11111 0 100 0001 10`, with monitor synchronization enabled, reports length 5 rather than 4.

### 5. [P1] Pause/resume publishes overlapping scan records

Location: `src/jtag_monitor_bfm.sv:70-80`.

Every exit from Shift publishes an OK scan, before knowing whether the operation will pause or update. Buffers remain populated when returning through Exit2 to Shift. A two-bit segment followed by another two-bit segment therefore publishes a prefix and then that prefix again inside a larger record. With the current capture bug the lengths are 3 and 5; fixing capture alone leaves overlapping lengths 2 and 4.

Choose an explicit contract: one accumulated scan with pause/interruption events, or distinct non-overlapping segments with continuation metadata. Define the observation boundary independently of driver intent and test reset during a paused operation.

### 6. [P1] Smoke test cannot detect a nonfunctional monitor

Location: `tb/tests/jtag_smoke_test.svh:25-37`.

The test only launches sequences, then drops its objection. It has no observation subscriber, expected count, data comparison, or timeout waiting for monitor output. It can finish with a completely silent monitor. Add a minimal self-checking subscriber and explicit expected results. The DUT is clearly documented as a loopback stub, so this test must not be presented as JTAG protocol verification. A real TAP DUT is still absent.

### 7. [P2] Observations silently discard X/Z information

Location: `src/jtag_monitor_bfm.sv:20-21`, `src/classes/jtag_types.svh:69-70`, and `src/classes/jtag_item.svh` response fields.

Pin values are four-state logic, but monitor queues and outgoing data arrays are two-state `bit`. Unknown/high-impedance TDO becomes zero before any subscriber can diagnose it. Preserve four-state samples through the observation path, or add explicit validity/error metadata. Unknown TMS also needs a synchronization policy rather than coercion through a `bit` function argument.

Acceptance: inject X/Z on observed pins and require retained values or a defined error event.

### 8. [P2] Short TMS reset falsely sets predicted state to Reset

Location: `src/jtag_driver_bfm.sv:48-50`.

The API accepts any cycle count, including zero, then unconditionally forces the driver's prediction to TEST_LOGIC_RESET and returns success. From a non-reset state a short sequence need not reset the DUT. Validate the reset request, require enough clocks for a guaranteed reset, or retain the actual state reached. Randomization constraints alone are insufficient because callers can assign fields directly.

## Additional design follow-up

- Define explicit time units/precision in timing-bearing scopes and validate that the configured period produces nonzero half cycles. The current source/file list supplies no explicit timebase.
- Review TDO sampling at the falling edge against a real TAP and simulator scheduling; the posedge loopback stub cannot validate this timing contract.
- Runtime-check scan data size, positive length, and compatible IR/DR pause destinations before driving pins.
- Passive agent selection does not disable the driver's static initialization block; define static BFM enable/instantiation rules for passive integration.
- Configuration includes IR length and reset defaults that are not consumed by the supplied scan/reset sequences.
- The master proxy subclasses currently add no behavior. This is optional cleanup, not a protocol blocker.

## Assessment

The interface/BFM separation, abstract handles in UVM components, and per-agent configuration are useful scaffolding. The current code is not yet a verified JTAG UVC. First prove compilation and reset/monitor behavior; then add an independently implemented TAP and self-checking tests. Keep implementation claims tied to saved simulator logs and exact revisions.
